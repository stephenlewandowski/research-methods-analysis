# Rebuilding the teaching package

The classroom HTML and MP4 work without installing anything. Rebuilding requires
Python, the four packages in [requirements.txt](requirements.txt), and an FFmpeg
executable with the `libx264` encoder. The supported build starts from the package
directory in a repository checkout or an extracted teaching ZIP; it does not need
the original ChatGPT Work scratch directory or pre-rendered images.

## Install the build tools once

Validated environment: **Python 3.12.14**, **NumPy 2.5.4**, **SciPy 1.18.1**,
**Matplotlib 3.11.2**, **Pillow 12.3.0**, and **FFmpeg 9.0.1** on Windows.
`requirements.txt` pins the Python packages. Install Python and FFmpeg separately.
Use a virtual environment to keep the Python dependencies local to the project.

From this package directory in PowerShell:

```powershell
python -m venv ".venv"
& ".\.venv\Scripts\python.exe" -m pip install -r ".\requirements.txt"
ffmpeg -version
```

If `python` does not identify your intended Python installation, replace it with
that installation's full executable path. On macOS/Linux, use `python3` for the
first command and `.venv/bin/python` for subsequent Python commands. Add FFmpeg to
`PATH`, or supply its full executable path with `--ffmpeg` below.

## Rebuild everything

From this package directory in PowerShell:

```powershell
& ".\.venv\Scripts\python.exe" ".\source\build.py"
```

The default destination is this package directory, determined from the script's
location. The command regenerates the delivered media and data there. To keep
the checkout's delivered files while building into a separate directory:

```powershell
& ".\.venv\Scripts\python.exe" ".\source\build.py" --output-dir ".\build\classroom copy"
```

The script also works from any current working directory. For example, with the
repository and virtual environment at the paths shown here:

```powershell
& "C:\Projects\RSCH650\.venv\Scripts\python.exe" "C:\Projects\RSCH650\projects\t-test-teaching-package\source\build.py" --output-dir "C:\Projects\RSCH650\build output\t-test package"
```

To select an FFmpeg installation explicitly, add
`--ffmpeg "C:\path with spaces\ffmpeg.exe"`. Paths are passed as subprocess
arguments, so spaces in source and destination paths are supported. Relative
`--output-dir` paths are resolved against the current working directory; all
source inputs are resolved from the scripts' own location. The build overwrites
files with matching output names in the selected destination.

## Build sequence and outputs

`source/build.py` runs the necessary steps in order:

1. Generate the four synthetic teaching scenarios, `source/assets.json`, the
   independent-group CSV, and its self-contained SPSS syntax.
2. Render chapter previews and `poster.png`; write `source/timeline.json`.
3. Encode the 126-second MP4, including its on-screen captions.
4. Embed the new video and poster in the offline classroom HTML, create SRT/VTT
   caption files, verify the exported baseline data, copy the teaching documents
   and worked example, and create `RSCH650_T_Test_Teaching_Package.zip`.

The ZIP includes the classroom player, animation, captions, synthetic data, SPSS
syntax, worked-example files, instructor notes, build instructions, requirements,
editable source scripts/template, calculated assets/timeline, regression tests, and the review
with its supporting screenshots. It can be extracted and rebuilt using the same
commands. `poster.png` is embedded in the player. Intermediate `qa_*.png` images,
Python caches, virtual environments, and the ZIP itself are excluded from the ZIP.
The ZIP and preview files are ignored by Git in an in-place build.

The worked-example datasets and teaching documents are maintained source inputs
and copied to the selected destination; the animation build does not execute SPSS
or regenerate those documents. Follow the worked example's own instructions for
its statistical validation and SPSS procedure.

## Edit or run an individual stage

Edit `source/render_ttest.py` for scene content or plot behavior,
`source/build_ttest_assets.py` for the synthetic independent-group scenarios, and
`source/classroom_template.html` for the classroom player. The timeline is
generated by the renderer; changing only a generated JSON file will be replaced
on the next build. All text files are read and written as UTF-8.

Each stage accepts `--output-dir`; run them in this order if you need to inspect
intermediate output. These examples use the same destination for every step:

```powershell
& ".\.venv\Scripts\python.exe" ".\source\build_ttest_assets.py" --output-dir ".\build\classroom copy"
& ".\.venv\Scripts\python.exe" ".\source\render_ttest.py" --output-dir ".\build\classroom copy"
& ".\.venv\Scripts\python.exe" ".\source\render_ttest.py" --output-dir ".\build\classroom copy" --encode
& ".\.venv\Scripts\python.exe" ".\source\package_ttest.py" --output-dir ".\build\classroom copy"
```

Preview rendering must run before packaging because it creates the poster.
Encoding must run before packaging to embed the revised MP4. Packaging reads the
HTML template and documents from the source package, and generated data,
timeline, poster, and MP4 from the destination. It skips copying a file when the
source and destination are the same path, so the in-place default is supported.

## Verification and troubleshooting

The asset stage cross-checks Welch statistics against SciPy; packaging checks
that the rounded CSV reproduces the animation's baseline result and that the ZIP
passes its CRC check. A successful build is not a substitute for visually
reviewing changed scenes: open the new HTML in a browser, check all nine chapter
buttons, and check both the start and settled view of chapter 7 at **1:23**.

Run the regression checks from this package directory after installing the
requirements:

```powershell
& ".\.venv\Scripts\python.exe" -m unittest discover -s tests -v
```

If the active Python interpreter already has the dependencies, the equivalent
command is `python -m unittest discover -s tests -v`. The tests verify that
chapter 7's actual plotted points and displayed statistics agree from its first
frame, as well as checking the scenario calculations, paired example, chapter
timing/captions, and genuine native SPSS output against independent references.

If FFmpeg is missing, the complete build exits before producing outputs and
explains how to supply it. If an individual stage reports a missing asset,
poster, timeline, or video, run the preceding steps or use `source/build.py`.
Rendering takes longer than packaging; chapter-by-chapter encoding progress is
printed to the terminal. Keep all files from the checkout or extracted ZIP
together so its source scripts, player template, documentation, and worked
example remain available.

## Native SPSS validation

The [worked examples](spss-worked-example/) include native text/XML snapshots
from IBM SPSS Statistics **29.0.2.0**. The paired syntax includes descriptive
statistics, difference-score diagnostics, the paired test, and an equivalent
one-sample test on those differences. The XML retains full-precision numerical
cells even when the native display rounds a small p-value to `.000`.

To execute both examples again, use the Python launcher supplied by a licensed
SPSS installation. The ordinary rendering virtual environment is insufficient
because it does not contain the SPSS integration plug-in. On the Windows
installation used for validation, from this package directory:

```powershell
& "C:\Program Files\IBM\SPSS Statistics\statisticspython3.bat" -u ".\source\validate_spss.py" --output-dir ".\build\native-spss"
```

Replace the launcher path if your installation differs. The runner starts a
separate native backend without opening a GUI, submits both complete syntax
files, and exports genuine OMS text/XML tables. It checks the native mean
differences, SE, t, df, two-sided p, and confidence bounds against
`spss-worked-example/expected_results.json`
within an absolute tolerance of 1e-9 and writes `verified_results.json`. It
does not alter an open user's dataset. Regenerating plots for visual inspection
is also possible by running the paired syntax in SPSS's Syntax Editor.

Without SPSS, the independent standard-library calculation check remains
available:

```powershell
python ".\spss-worked-example\verify_expected_results.py"
```
